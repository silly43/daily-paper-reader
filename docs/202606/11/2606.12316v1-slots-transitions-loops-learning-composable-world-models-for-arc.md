## 摘要
ARC测试上下文中的规则归纳：给定几个输入-输出演示，模型必须推断隐藏规则并将其应用于新的查询。虽然许多方法通过语言、代码或符号程序来表达ARC规则，但ARC本身是视觉-符号的：规则表现为对象、颜色、形状和空间关系上的网格转换。我们引入了Loop-OWM，一种以对象为中心的世界建模架构，它将这些规则学习为结构化状态上的可组合转换。它结合了颜色原型槽位、演示条件任务摘要，以及具有密集传播和槽位条件校正的循环转换模型。在ARC-1和ARC-2上，Loop-OWM以相当或更少的参数优于非循环和循环基线。这些结果表明，ARC规则不仅可以作为语言描述或搜索程序来学习，还可以作为视觉-符号世界状态上的转换来学习。

## Abstract
ARC tests in-context rule induction: given a few input-output demonstrations, a model must infer the hidden rule and apply it to a new query. While many approaches express ARC rules through language, code, or symbolic programs, ARC itself is visual-symbolic: rules appear as grid transitions over objects, colors, shapes, and spatial relations. We introduce Loop-OWM, an object-centric world-modeling architecture that learns these rules as composable transitions over structured states. It combines color-prototype slots, demonstration-conditioned task summaries, and a looped transition model with dense propagation and slot-conditioned correction. On both ARC-1 and ARC-2, Loop-OWM outperforms non-looped and looped baselines with comparable or fewer parameters. These results suggest that ARC rules can be learned not only as language descriptions or searched programs, but also as transitions over visual-symbolic world states.

### 6. 论文的主要结论与发现

- **主要结论**：Loop‑OWM 在 ARC‑1 和 ARC‑2 上均显著优于同等规模的循环/非循环基线，在紧凑神经系统中达到最佳性能（ARC‑1 68.5%，ARC‑2 22.5%）。这证明 ARC 规则可以通过**视觉‑符号状态上的可组成转换**进行学习，而无需显式的语言或符号程序。
- **关键发现**：
  - 互补更新（密集传输 + 槽条件写入）优于纯传输或纯槽更新，表明 ARC 转换需要同时支持信息路由和内容修改。
  - 混合任务摘要（共享 + 每任务）略优于纯每任务摘要，而纯共享摘要表现最差，表明任务专用容量对增强规则推理很重要。
  - 跨基准迁移（ARC‑1 → ARC‑2）显著加速收敛并提升离线验证准确率，证明学习到的视觉‑符号机制具有可迁移性。

### 7. 优点

- **方法创新**：
  - **对象中心世界模型**：将 ARC 任务形式化为槽‑状态转换，与 ARC 的对象索引自然对齐。
  - **颜色原型槽初始化**：利用 ARC 颜色作为固定锚点，提供跨任务一致的槽身份，减少位置恒等偏置。
  - **组合过渡监督**：通过监督总组合转移矩阵，迫使多步 rollout 维持正确的整体变换，比仅监督最后一步更有效。
  - **模块化设计**：编码器、循环核心、解码器分工明确，便于消融分析。
- **实验严谨**：
  - 使用程序性增强生成大量训练数据，同时保证评价集无泄漏。
  - 两阶段训练（离线 + 测试时）适应 ARC 的少样本特性。
  - 消融实验聚焦核心设计，结论直观。
- **资源效率**：模型参数仅约 10.6M，远小于 LLM 方案，推理成本低，适合资源受限场景。

### 8. 不足与局限

- **中间状态缺乏语义解释**：如图 3 所示，循环步骤的中间输出没有稳定的跨任务语义（如定位、传输、着色等阶段）。模型没有受到中间状态监督，导致 rollout 内部表示不可解释。
