## 摘要
基于大型语言模型（LLM）的智能体越来越多地用于交互式文本环境，从网页导航、代码编辑到工具使用和长程对话。然而，许多智能体在很大程度上仍是被动的，将观察映射到行动，而没有对这些环境的结构和演变进行显式建模。这促使了文本世界模型（TWM）的发展：即文本状态的转移模型，给定一个状态和一个候选动作，预测生成的网页、终端输出、API响应或用户回复，从而支持规划、高效学习和有原则的评估。我们系统性综述了基于LLM的智能体的文本世界模型，围绕一个形式化框架和智能体生命周期进行组织：（1）基础，定义文本世界模型，并通过状态表示和基础领域对其进行刻画；（2）构建，对“LLM作为世界模型”和“代码作为世界模型”两种范式进行分类，并回顾构建这些模型的方法；（3）应用，考察世界模型如何在训练时通过经验合成、在推理时通过规划、验证和适应来支持智能体；（4）评估，涵盖世界模型本身的评估以及将其用作智能体的评估环境。我们旨在整合这一快速发展的领域，阐明其设计空间，并指出未来研究中的开放挑战。

## Abstract
Large language model (LLM)-based agents are increasingly used in interactive textual environments, from web navigation and code editing to tool use and long-horizon dialogue. Yet many remain largely reactive, mapping observations to actions without an explicit model of how these environments are structured and evolve. This motivates text world models (TWMs): transition models over textual states that, given a state and a candidate action, predict the resulting webpage, terminal output, API response, or user reply, thereby supporting planning, efficient learning, and principled evaluation. We systematically review text world models for LLM-based agents, organized around a formal framework and the agent lifecycle: (1) Foundations, defining text world models and characterizing them by state representation and grounding domain; (2) Construction, taxonomizing LLM-as-WM and code-as-WM paradigms and reviewing methods for building them; (3) Application, examining how world models support agents at training time through experience synthesis and at inference time through planning, verification, and adaptation; and (4) Evaluation, covering both evaluation of the world model itself and its use as an evaluation environment for agents. We aim to consolidate this rapidly developing area, clarify its design space, and highlight open challenges for future research.

## 2. 方法论：核心思想、关键技术细节与形式化框架

### 2.1 形式化定义
- **文本世界模型**定义为转移函数：\(M : S \times A \rightarrow T_S\)，其中输入当前状态 \(s_t\) 和动作 \(a_t\)，输出后续状态的文本渲染 \(\hat{s}_{t+1}\)。输入状态可以是文本或多模态（如对话历史、终端日志、网页截图），输出必须是文本形式。
- 覆盖两类交互目标：**外部环境建模**（网页、软件、API）和**用户建模**（对话中的偏好、意图、任务进度）。

### 2.2 二维分类轴
- **轴1：状态/转移表示**——从灵活到形式化：
  - 自然语言（自由形式描述，易生成但弱约束）
  - 结构化表示（JSON、知识图谱、可访问性树、PDDL谓词，易跟踪和验证）
  - 可执行代码（Python、TypeScript、HTML等，精确执行，强可验证性）
- **轴2：基础领域**：
  - 物理世界（家用、游戏物理、灾害场景）
  - 数字世界（网页、代码库、终端、GUI）
  - 社会世界（用户对话、偏好、情感）
  - 抽象世界（数学、规划、逻辑谜题）

### 2.3 构建范式
- **学习型（LLM-as-WM）**：
  - **监督微调（SFT）**：在 \((s_t, a_t, s_{t+1})\) 三元组上训练，预测完整下一状态或仅预测变化（delta）。数据来源从真实环境收集到全合成；数据规模从数千到万亿token。
  - **强化学习（RL）**：优化预测质量的奖励，从字符串级匹配→语义等价→行为一致性→潜在一致性，奖励信号逐步远离表面匹配，逼近下游决策价值。
- **提示型（LLM-as-WM）**：
  - **上下文世界建模**：直接冻结LLM，通过提示预测转移，受限于LLM先验知识。
  - **检索增强**：从外部知识库（教程、专家轨迹）检索相关信息，缓解错误累积。
  - **自演进**：在交互过程中积累经验，提炼因果规则或程序化启发式，注入后续提示。
- **程序化（Code-as-WM）**：
  - 使用LLM生成可执行代码（PDDL、Python、HTML模拟器）作为世界模型，转移由代码执行器确定性完成，具有可验证、可复现、可分离的优点。
- **跨范式对比**：学习中知识隐含在参数中（高保真、低可验证性）；提示型知识表面化（快速适应、易幻觉）；程序化知识作为独立制品（确定性、可验证、可复用）。

### 2.4 使用阶段
- **训练时使用**：
  1. **内部化世界模型**：将世界模型融入智能体参数（作为热身信号或推理痕迹中的显式预测），避免外部模拟器依赖。
  2. **作为训练环境**：离线合成轨迹→在线WM-as-Env（提供每一步观察和奖励）→共演化（智能体与世界模型同时更新）。
  3. **用户模拟**：模拟人类用户，支持RL训练（从合作用户到模糊、情绪化、持有个性的用户）。
- **推理时使用**：
  1. **作为模拟器**：浅层前瞻（单步或少数步模拟后选优）和深层树搜索（如MCTS，多步规划）。
  2. **作为验证器**：单一动作门控→多候选排名→低置信时重生成/修正。

## 6. 主要结论与发现

- **核心发现**：文本世界模型可以显著提升LLM智能体的规划、学习和评估能力，但当前方法在开放域中预测精度随步数衰减迅速，行为一致性比表面匹配更重要。
- **构建层面**：
  - 数据规模随环境开放性从10^4到5T token，闭合环境饱和快，开放环境需更大规模。
  - RL训练优于SFT，特别是行为一致性奖励（BehR）优于语义或表面匹配。
  - 程序化环境合成使环境数量成为独立扩展轴，且多样性比纯数量更重要。
- **使用层面**：
  - 训练时使用中，在线WM-as-Env和共演化比离线合成更能缩小分布差距，但存在幻觉漂移。
  - 用户模拟必须建模忠实度，否则过度合作的模拟器会高估智能体能力。
  - 推理时，浅层前瞻适用于有限步骤，树搜索解决长程规划，验证器可纠正错误但不处理动作生成。
- **评估层面**：
  - 单步精确匹配不能保证任务成功，环境理解与任务成功可解耦（Task2Quiz）。
  - 模拟器本身需要被评估：当前prompted LLM作为用户模拟器存在系统性乐观偏差，且对人口统计学子群体不均衡。
