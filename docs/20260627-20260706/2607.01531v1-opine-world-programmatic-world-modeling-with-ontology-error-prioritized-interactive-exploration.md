## 摘要
从交互中学习环境的行为是构建适应不熟悉任务的智能体的核心。使用深度网络学习的世界模型灵活但数据需求大，且在其训练分布之外迁移性差。而通过LLM编写为源代码，并通过反例引导归纳合成（CEGIS）精炼的程序合成世界模型则数据高效且可重用，但它们主要展示在具有给定对象词汇的结构化状态世界上，且单一的程序搜索无法扩展到需要灵活假设对象结构的像素渲染环境。我们引入OPINE-World，一个从交互中在线学习以对象为中心的程序化世界模型的LLM智能体。OPINE-World在假设与测试的循环中耦合两个协作智能体，一个在环境中行动，另一个通过回放验证和基于模型的规划以代码形式合成模型，并通过称为本体错误的贝叶斯对象类型充分性度量来引导探索。我们在ARC-AGI-3上评估OPINE-World，这是一个技能获取效率基准，其中对象词汇、目标和动作语义均被隐藏。OPINE-World在无需逐游戏训练的情况下解决了25个游戏中的20个，并达到了相对于人类基线78.4的动作效率分数。

## Abstract
Learning how an environment behaves from interaction is central to building agents that adapt to unfamiliar tasks. World models learned with deep networks are flexible but data-hungry and transfer poorly beyond their training distribution. Program-synthesized world models, written as source code by LLMs and refined through counterexample-guided inductive synthesis (CEGIS), are instead data-efficient and reusable, yet they have been demonstrated mainly on structured-state worlds with a given object vocabulary, and a single program search does not scale to pixel-rendered environments whose object structure must be hypothesized flexibly. We introduce OPINE-World, an LLM agent that learns an object-centric programmatic world model online from interaction. OPINE-World couples two cooperating agents in a loop of hypothesis and test, one acting in the environment and one synthesizing the model in code with replay verification and model-based planning, and it steers exploration with a Bayesian measure of object-type adequacy we call ontology error. We evaluate OPINE-World on ARC-AGI-3, a benchmark for skill-acquisition efficiency in which the object vocabulary, the goal, and the action semantics are withheld. OPINE-World solves 20 of 25 games without per-game training and reaches an action-efficiency score of 78.4 against the human baseline.

### 2. 论文提出的方法论：核心思想、关键技术细节

- **整体框架**：OPINE-World 运行一个**假设与测试的循环**，由两个协同的 LLM 智能体共享一块经验回放缓冲区：
  - **行动智能体（Goal-directed Agent）**：与环境交互，基于自然语言维护的初步模型提出假设并探索，收集转移数据。
  - **模型合成智能体（World-Model Agent）**：从缓冲区读取数据，合成并修复以**对象类型为中心**的 Python 程序模型，通过**精确重放验证**（exact replay check）才接受模型。
- **关键技术细节**：

  1. **对象中心世界模型**：状态表示为带类型的对象集合 $o_{it} = (\kappa_{it}, \tau_{it}, v_{it})$。每个类型 $\tau$ 拥有一个共享的转移规则 $f_\tau: O_\tau \times A \times X \to O_\tau$，其中 $X$ 是局部上下文（例如周围障碍物）。模型组织为按类型分组的程序，使得一个规则可应用于该类型所有对象。

  2. **双智能体协作**：
     - 行动智能体**提出关于动力学和目标的假设**（通过自然语言世界模型和当前合成代码），并在环境中测试。
     - 合成智能体将假设**转化为代码**，提交给精确重放检查（必须复制缓冲区中每一对转换）。此外还有一个周期性运行的**评判器（Critic）**，挑战当前模型的弱泛化能力，防止过拟合到单一关卡。

  3. **精确重放验证与反例引导合成**：
     - 接受条件：$\phi_T(\hat{T}, D_t): \hat{T}(s_\ell, a_\ell) = s_{\ell+1}$ 对所有 $\ell$ 成立，且程序运行两次结果必须一致（排除隐藏状态）。
     - 合成仅在模型预测与观察不符（出现反例）时触发；设有延迟窗口和停滞守卫避免频繁重写。

  4. **本体错误（Ontology Error）**：一种**贝叶斯诊断度量**，通过**效果签名**（只记录哪些属性改变，不记录具体值）构建局部效果表，然后计算每个对象-行的不确定性：
     - 类型不确定性 $U_{\text{type}}^i$：基于 Dirichlet 后验的对象类型熵。
     - 行不确定性 $U_{\text{row}}^j$：给定类型-动作-上下文下效果分布的归一化熵。
     - 组合为本体错误 $\eta_{it} = 1 - (1-U_{\text{type}}^i)(1-U_{\text{row}}^{j_{it}})$，聚合为 $\eta_t$。高 $\eta_t$ 指示当前类型未能解释的对象，引导探索。

  5. **规划与执行**：当模型被接受且至少一个关卡通过后，合成一个基于模型的前向搜索规划器；首先在已通过关卡上离线验证规划，然后逐步在线执行；若实际步长与预测不符，则作为反例返回缓冲区。
