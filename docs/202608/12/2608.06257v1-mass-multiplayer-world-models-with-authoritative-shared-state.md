## 摘要
当前视频世界模型在多玩家环境中存在困难，因为它们将世界状态与依赖于视图的视觉潜变量纠缠在一起，导致计算冗余、视图不一致和可扩展性差。我们提出了MAS（具有权威共享状态的多玩家世界模型）来解决这一限制。受多玩家游戏架构的启发，MAS将世界动力学与视图渲染分离。一个学习到的逻辑引擎根据联合动作推进全局、权威的类型化状态，无需任何手写转换函数，并作为唯一的循环记忆和同步参考。从这个共享状态出发，一个学习到的渲染引擎按需为任何请求的视图生成独立且一致的视图。这种显式解耦使MAS在匹配的多玩家Snake基准测试中，与最先进的多视图基线相比，实现了更好的状态准确性和更低的跨视图不一致性。它推进了包含1024个并发玩家、10000个循环步骤的预测世界。我们的结果表明，显式、权威的状态建模为可扩展且一致的多智能体世界模拟提供了实用基础。

## Abstract
Current video world models struggle in multiplayer environments because they entangle world state with view-dependent visual latents, leading to redundant compute, view inconsistencies, and poor scalability. We propose MAS (Multiplayer world models with Authoritative Shared State) to resolve this limitation. Inspired by multiplayer game architectures, MAS disentangles world dynamics and view rendering. A learned Logic Engine advances a global, authoritative typed state from joint actions without any hand-written transition function, acting as the sole recurrent memory and synchronization reference. From this shared state, a learned Rendering Engine generates independent and consistent views for any requested camera on demand. This explicit disentangling allows MAS to achieve superior state accuracy and lower cross-view inconsistency compared to state-of-the-art multi-view baselines on a matched multiplayer Snake benchmark. It advances predicted worlds with 1,024 concurrent players for 10,000 recurrent steps. Our results show that explicit, authoritative state modeling provides a practical foundation for scalable and consistent multi-agent world simulation.

## 1. 核心问题与整体含义

**研究动机与背景**：现有视频世界模型（如 GameNGen、Oasis、DIAMOND、Genie 等）以像素或视觉潜变量作为循环记忆载体，将“世界状态”与“视角相关的外观信息”纠缠在一起。这种设计在单玩家场景中可行，但在多玩家场景中会引发三方面问题：

- **计算冗余**：多个玩家视角各自维护独立的循环视觉历史，相当于对同一共享内容编码多次，需要为每个视角单独运行一次世界模拟，导致世界推进成本与观看视角数量成正比。
- **视角不一致**：各个视角的循环历史由不同目标驱动，可能逐渐漂移，导致同一世界中的不同相机看到互相矛盾的实体状态。
- **扩展性差**：无法支持大规模并发玩家世界（如 1,024 个玩家同时存在于一个世界中）。

**整体含义**：MASS 借鉴在线多人游戏架构中“权威服务器 + 客户端渲染”的成熟范式，将世界动力学（负责推进世界状态）与视图渲染（负责从状态生成画面）显式解耦，以“类型化权威状态”作为唯一的循环记忆和同步基准，从而在根本上解决上述问题。

## 2. 方法论

### 核心思想

MASS 将"世界如何演化"与"画面如何呈现"彻底分离：

- **世界状态** 是一个由游戏 schema 声明的、可序列化的、类型化实体记录集合，作为唯一的循环记忆；
- **逻辑引擎**（Logic Engine）基于当前状态、联合玩家动作和外部随机输入，预测下一时刻的完整类型化状态，无需任何手写转移函数；
- **渲染引擎**（Rendering Engine）从同一个预测状态出发，按需为任意数量的相机生成独立且一致的视图。

### 关键技术细节

**(1) 世界状态 Tokenizer（World State Tokenizer）**

- 每个游戏通过一个声明式 schema 定义实体种类、字段及数量上限：
  $$\Sigma_g = \{(\text{kind}_j, \text{fields}_j, \text{count}_j)\}_{j=1}^{J_g}$$
- 世界状态是所有类型化实体记录的集合：
  $$s_t = \{\rho_t^1, \dots, \rho_t^{K_g}\}, \quad K_g = \sum_j \text{count}_j$$
- 每个记录通过 tokenizer 转换为固定位置序列，包含字段值、局部空间上下文窗口、绑定的玩家动作和随机性输入：
  $$u_t^i = T_{\Sigma_g}(\rho_t^i, c_t^i, a_{\pi(i)}^t, e_t^i)$$
- 类型标签、字段掩码和确定性选择器保证解码出的状态总是结构合法。

**(2) 逻辑引擎（Logic Engine）**

- 使用 decoder-only Transformer（宽度 256、6 层、8 头，约 5.66M 参数），将完整状态、全部玩家动作和外部输入作为条件，自回归预测下一状态的所有字段：
  $$\hat{s}_{t+1} = F_\theta(\hat{s}_t, a_t, e_t)$$
- 概率分解为记录级因子乘积：
  $$p_\theta(s_{t+1} | s_t, a_t, e_t) \approx \prod_{i=1}^{K_g} \prod_j p_\theta(y_{t+1}^{i,j} | u_t^i, y_{t+1}^{i,<j})$$
- 采用记录间无注意力（self-attention 局限于单条记录内）的分解设计，使模型能以批处理方式处理 1,024 个实体的大规模世界；实体间的交互通过从共享状态预计算的邻域上下文窗口 $c_t^i$ 传入。
- schema 派生掩码确保输出字段合法性，确定性选择器强制执行排序、去重等跨记录约束；所有游戏动力学（移动、碰撞、成长、收集、死亡）都是学习结果而非规则编码。

**(3) 渲染引擎（Rendering Engine）**

- 将每个相机通过确定性投影 $P_i$ 把共享预测状态转为 16 通道的相机局部张量（包含可见占用、语义角色、归属、玩家身份、几何信息等）；
- 一个几何感知的 residual U-Net 将该张量渲染为 RGB 帧：
  $$\hat{o}_t^i = R_\phi(P_i(\hat{s}_t), \kappa_i)$$
- 渲染过程可并行地为任意数量相机服务，成本仅与请求的相机数量线性相关，与世界规模无关。

**(4) 服务器 / 客户端逻辑**

- 每个 tick 逻辑引擎只运行一次，发布带版本的权威类型化快照；
- 服务器每 tick 成本为：
  $$T_{\text{server}} = T_{\text{logic}}(N) + C \cdot t_{\text{sync}}(S)$$
  其中世界推进 $T_{\text{logic}}(N)$ 与相机数量 $C$ 无关；
- 客户端缓存最新版本状态，在服务器更新中断期间，可用同一逻辑引擎从本地缓存状态继续推进世界，以自身动作作为输入、其他玩家置为 no-op，从而保持本地响应性；新权威版本到达后直接替换推测状态。

## 6. 主要结论与发现

1. **类型化状态显著优于视觉潜变量**：匹配 Snake 基准上 MASS 取得 0.764 的状态恢复率（Parser），远超最强视频基线 B-PV 的 0.128；LPIPS 为 0.098（最低），X-view 不一致率为 0.000（由构造保证）。

2. **稠密状态网格无法保持实体身份**：B-UN 尽管 LPIPS 接近（0.123），但 Parser 恢复率降至 0，说明"像素相似"与"世界状态可恢复"是两回事。

3. **跨游戏架构复用可行**：同一套逻辑引擎 + 渲染引擎架构，仅替换 schema、tokenizer 和权重，即可支持 8 个不同游戏的渲染和 3 个游戏的逻辑预测，且多数游戏 PSNR 超过 32 dB。

4. **长 horizon 结构稳定性好**：1,024 个玩家实体可推进 10,000 个循环步骤且不崩溃；H=4,096 时保持全部实体存活、零结构非法状态。

5. **客户端预测能力**：在服务器更新中断时，本地使用相同逻辑引擎可从最新权威状态继续推进世界，本地玩家位置在 8 tick 内零位移偏差；下降主要来自未知的远端动作而非学习转移函数。

6. **解耦可实现错误定位**：SRSC 显示 Snake 渲染器在参考状态上的评分保持 63.8–75.0 无单调下降，说明端到端性能衰减主要来自动力学而非渲染。

## 7. 优点

- **原创性强的架构贡献**：将多人游戏网络架构中的"权威服务器"思想系统化引入学习式世界模型，以类型化状态作为循环记忆和同步对象的双重角色，概念清晰、实现彻底（状态不仅是循环记忆，还是版本化同步消息和渲染的唯一输入源）。
- **可验证性与可诊断性**：类型化状态允许在生成任何帧之前直接评估语义正确性（实体持久性、位置准确率、结构合法性），弥补了视频世界模型难以度量"预测是否语义有效"的空白；SRSC 协议实现了逻辑与渲染错误的分离定位。
- **规模与效率优势**：通过"记录间无注意力 + 邻域上下文窗"的分解式架构，世界推进成本与渲染视角数解耦，使 1,024 玩家、10,000 步的大规模模拟成为可能。
- **良好的泛化架构**：schema 驱动的声明式设计使新游戏接入无需改进架构，论文报告三个游戏可在一晚完成整合。
- **实验严谨性**：匹配基准协议、冻结解析器阈值验证、SRSC 协议哈希绑定等设计保证了对比与评估的公平性和可审计性。
- **工程实用性**：版本化状态支持客户端断线预测和状态对账，为实际部署提供了明确路径。

## 8. 不足与局限

- **实验场景维度有限**：所有实验均为 2D（或 2.5D）俯视角游戏，未验证 3D 环境（算法在正文中未出现引理编号，且 3D 扩展仅作为 future work）。丰富实体交互（如物理接触、通信协议）的模拟也尚未覆盖。
- **算力披露不足**：论文未提供 GPU 型号/数量、总训练 GPU-hours 等关键训练

成本指标，难以评估方法在更大规模数据集上的可复现性与性价比；这一缺失在与其他工作做算力对比时尤其关键。

- **架构的表达力边界未充分刻画**：记录间无注意力设计虽然带来了规模优势，但也意味着所有跨实体交互必须预先压缩进有限大小的局部上下文窗口 $c_t^i$。对于需要长程、全局或非局部交互的游戏逻辑（如全局视野内的合作策略、远距离通信、跨房间因果传播），该窗口可能成为瓶颈，论文对此没有量化实验。

- **对视觉外观细节的建模相对粗糙**：MASS 的渲染质量在 PSNR/LPIPS 上虽优于部分基线，但受限于稠密局部张量（16 通道）的描述能力，文本（文字、UI 元素）、复杂光照、透明/反射材质等细节在少数游戏中无法被完整重建；论文未报告这些特定外观成分的失败案例分析。

- **评测基准的生态代表性有限**：论文自建了 8 个简单游戏的基准协议，但未在社区通用的开放世界视频基准（如 MineDojo、Habitat 等）上验证；同时"匹配协议"虽公平，却使得基线方法（如扩散模型）无法发挥其训练数据的先验优势。

- **跨视角一致性的"保证"依赖于架构假设**：X-view 不一致率为 0 是由"所有视角从同一状态渲染"的构造直接推出的，因此该指标在比较中更多是结构性结果而非行为学上的验证。论文未测试渲染引擎在极端相机位姿差异下的几何一致性退化情况。

- **多玩家动作规模与类型受限**：所有实验中的动作均为离散低维控制（方向键等），多玩家策略仅表现为空间上的避让与竞争；真实多人游戏中的复杂交互（聊天、交易、组队目标、非对称信息）未被纳入。

## 9. 总结性结论

MASS 的核心贡献在于提出了一种"权威状态驱动的解耦式世界模型"范式：以可序列化、类型化的实体状态作为唯一的循环记忆、唯一的跨进程同步对象以及唯一的渲染输入源，从而将世界侧的计算复杂度与观众数量解耦。实验表明，这一设计在多人场景下显著优于耦合的视觉潜变量方法，在语义状态恢复率（0.764 vs. 0.128）和感知质量（LPIPS 0.098）上均取得明显优势；同时该范式能够以极低的参数量（约 5.66M 逻辑模型）支撑 1,024 实体、万步级的长 horizon 模拟，并通过版本化快照天然支持客户端断线预测。

从方法论长期发展的视角看，该工作提示了一条值得重视的研究路线：在生成式世界模型中，"对世界的语义理解"与"对画面的像素合成"应当被显式分离，前者负责因果与一致性，后者负责感知与呈现。这种分离不仅带来计算效率上的收益，更重要的是提供了调试、审计和逐步部署的接口。然而，当前实现仍局限于 2D 小型游戏、局部交互和有限动作空间，其向 3D 连续空间、复杂语义交互与大规模开放世界迁移的可行性，仍需要后续工作系统性验证。

## 10. 重要概念速查表

| 概念 | 含义 |
|---|---|
| 类型化状态（typed state） | 由 schema 声明的、可序列化的实体记录集合，是 MASS 的循环记忆与同步对象 |
| 逻辑引擎（Logic Engine） | 基于当前状态、动作与随机噪声，学习预测下一时刻完整状态的 Transformer |
| 渲染引擎（Rendering Engine） | 将共享状态按相机投影为稠密张量，再经 U-Net 生成 RGB 视图的模块 |
| Lambda（$\Sigma_g$） | 游戏 g 的声明式 schema，定义实体种类、字段与数量上限 |
| 记录级无注意力分解 | 自回归预测时 self-attention 限制在单条记录内，使批处理可扩展到上千实体 |
| 匹配基准协议 | 所有方法共享完全相同的测试初始条件、动作流、相机路径与优化预算的评价协议 |
| SRSC | 基于 VLM 的语义正确性评分，用于分离逻辑误差与渲染误差 |
| 预测-校正同步 | 客户端用本地逻辑引擎推进推测状态，收到权威版本后直接替换的状态同步策略 |
| X-view 不一致率 | 不同视角渲染结果之间语义不一致的比例，MASS 中由构造保证为 0 |
