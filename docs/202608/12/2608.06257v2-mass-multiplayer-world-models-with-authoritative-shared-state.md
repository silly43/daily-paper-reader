## 摘要
当前的视频世界模型在多玩家环境中面临困难，因为它们将世界状态与依赖视角的视觉潜在变量纠缠在一起，导致冗余计算、视角不一致和可扩展性差。我们提出MASS（具有权威共享状态的多玩家世界模型）来解决这一限制。受多玩家游戏架构的启发，MASS将世界动态和视角渲染分离开来。一个学习到的逻辑引擎从联合动作中推进一个全局、权威的类型化状态，无需任何手写转换函数，并作为唯一的循环记忆和同步参考。从这个共享状态出发，一个学习到的渲染引擎按需为任何请求的相机生成独立且一致的视角。这种显式的分离使得MASS在匹配的多玩家Snake基准上，与最先进的多视角基线相比，能够实现更优越的状态准确性和更低的跨视角不一致性。它能够为1,024个并发玩家推进预测世界10,000个循环步骤。我们的结果表明，显式的权威状态建模为可扩展且一致的多智能体世界模拟提供了实用基础。

## Abstract
Current video world models struggle in multiplayer environments because they entangle world state with view-dependent visual latents, leading to redundant compute, view inconsistencies, and poor scalability. We propose MASS (Multiplayer world models with Authoritative Shared State) to resolve this limitation. Inspired by multiplayer game architectures, MASS disentangles world dynamics and view rendering. A learned Logic Engine advances a global, authoritative typed state from joint actions without any hand-written transition function, acting as the sole recurrent memory and synchronization reference. From this shared state, a learned Rendering Engine generates independent and consistent views for any requested camera on demand. This explicit disentangling allows MASS to achieve superior state accuracy and lower cross-view inconsistency compared to state-of-the-art multi-view baselines on a matched multiplayer Snake benchmark. It advances predicted worlds with 1,024 concurrent players for 10,000 recurrent steps. Our results show that explicit, authoritative state modeling provides a practical foundation for scalable and consistent multi-agent world simulation.

## 1. 核心问题与研究动机

现有视频世界模型（如GameNGen、Oasis、DIAMOND等）在单玩家场景表现良好，但在多玩家环境中存在根本性缺陷：

- **状态与视觉纠缠**：这些模型将世界状态与像素/视觉潜变量绑定，每个相机关联一条独立的循环历史。这意味着同一世界内容被重复编码多次，造成**大量冗余计算**。
- **视图不一致**：不同相机各自维护独立的历史，对于同一实体可能产生相互矛盾的预测结果。
- **可扩展性差**：模拟世界的计算成本随观看视图数量线性增长，而非随世界本身规模增长。一千个玩家共享一个世界，但每个相机只看到其中一小部分，却要独立维护整条视觉历史。

论文指出，在线多人游戏早已解决了这一问题：权威服务器只推进一份规范游戏状态，客户端接收带版本号的快照并渲染各自视角——**世界只被模拟一次，与渲染它的客户端数量无关**。MASS的核心动机就是将这一成熟架构思想引入学习型世界模型，实现“一次世界推进、任意视图渲染”。

## 2. 方法论

### 2.1 总体框架

MASS将世界动态与视角渲染**显式解耦**，由两个独立学习模块组成：
- **逻辑引擎（Logic Engine）**：推进全局权威类型化状态，是唯一的循环记忆与同步参考。
- **渲染引擎（Rendering Engine）**：从共享状态出发，按需为任意相机生成一致的视图。

### 2.2 世界状态分词器

- 每个游戏通过**声明式 schema** 定义类型化实体：$\Sigma_g = \{(\text{kind}_j, \text{fields}_j, \text{count}_j)\}_{j=1}^{J_g}$。
- 每个实体被转换为固定长度的 token 序列：$u_i^t = T_{\Sigma_g}(\rho_i^t, c_i^t, a_{\pi(i)}^t, e_i^t)$，其中 $c_i^t$ 是局部邻域上下文、$a_{\pi(i)}^t$ 是关联玩家动作、$e_i^t$ 是外源随机输入。
- 采用有界、schema 定义的布局，保证状态可无损序列化与解码，并支持高效的批处理。

### 2.3 逻辑引擎

- 使用 decoder-only Transformer，核心转移函数为：
$$\hat{s}_{t+1} = F_\theta(\hat{s}_t, a_t, e_t)$$
- 记录级预测因子分解为：
$$p_\theta(s_{t+1} | s_t, a_t, e_t) \approx \prod_{i=1}^{K_g} \prod_j p_\theta(y_{i,j}^{t+1} | u_i^t, y_{i,<j}^{t+1})$$
- **实体间无注意力交互**，交互通过当前状态预先计算的邻域窗口 $c_i^t$ 进入，这使得 1,024 实体规模的世界成为可能。
- Schema 推导出的掩码限制输出位置只能取合法值，确定性选择器（如排序、唯一性约束）在解码时强制执行结构约束。

### 2.4 渲染引擎

- 对相机 $i$，先执行确定性投影 $P_i(\hat{s}_t)$，将可见单元格、实体归属、玩家身份、视图几何等信息写入相机局部张量。
- 学习型残差 U-Net 将该张量转换为 RGB 帧：$\hat{o}_t^i = R_\phi(P_i(\hat{s}_t), \kappa_i)$。
- 所有视图从同一共享状态解码，因此**天然一致**，外观差异仅由渲染器控制。

### 2.5 权威服务器与客户端逻辑

- 服务器每 tick 执行一次全局转移，发布**带版本号的类型化快照**。
- 每 tick 的服务端负载为：$T_{\text{server}} = T_{\text{logic}}(N) + C \cdot t_{\text{sync}}(S)$，世界转移仅运行一次，分发与 C 线性相关，渲染在客户端本地完成。
- 当服务器更新中断时，客户端可用同一逻辑引擎从最新权威状态**本地推进**，仅使用自身动作，维持响应性。

## 6. 主要结论

1. **解耦有效**：MASS 在匹配 Snake 基准上 Parser 状态恢复达 0.764，是最强视频基线的 5 倍以上；跨视图不一致率为 0.000（构造性保证）。
2. **像素相似 ≠ 世界可恢复**：B-UN 的 LPIPS 与 MASS 接近（0.123 vs 0.098），但状态解析率近乎为零，说明视觉逼真度不能代表世界状态正确性。
3. **类型化载体优于密集载体**：所有密集状态预测器在位置精度上几乎为零，而 MASS 保持高精度且零结构矛盾。
4. **可扩展性成立**：同一学习转移架构可推进 1,024 并发玩家、10,000 步循环推演，世界推进成本与渲染视图数量无关。
5. **schema 机制通用**：同一 Transformer 架构通过声明式 schema 即可适配多个游戏，无需修改核心架构。

## 7. 方法优点

- **架构创新性强**：将在线游戏成熟的“权威服务器-客户端渲染”架构引入学习型世界模型，视角新颖且实用。
- **状态显式可评估**：类型化状态允许在渲染前直接度量动态正确性，实现错误定位（逻辑误差 vs 渲染误差）。

- **计算成本解耦**：世界推进成本与视图/客户数量无关，与多人游戏的效率模型一致。
- **丰富实验设计**：包含 8 个游戏、多规模实体、长程稳定性、消融研究和 SRSC 语义评估，验证全面。

## 8. 不足与局限

### 实验覆盖局限
- **仅验证 2D 网格游戏**：所有 8 个游戏均为 2D 网格类，未涉及 3D 环境（论文承认这是未来方向）、物理机器人或具身智能场景。
- **主基准单一**：核心定量对比只在一个 Snake 游戏上进行，博弈复杂度有限。
- **视觉风格差异**：跨游戏的渲染器为各自独立训练，未验证单一渲染器的跨游戏泛化能力。

### 方法局限
- **Schema 设计依赖人工**：声明式 schema 需要领域知识手工设计，实体种类、字段范围和上下文窗口的选择缺乏自动化。
- **外源输入需求**：逻辑引擎依赖显式外源随机输入（如食物生成的随机种子），在无该信息的环境中可能限制适用性。
- **局部交互窗口限制**：实体间信息传递依赖有限半径的邻域窗口，远距离关系或全局结构可能无法学习。
- **渲染器输入受限**：渲染器无法利用 RGB 历史，在需要运动模糊、光照渐变等视觉时间一致性效果时可能表现不佳。

### 潜在偏差风险
- **VLM 评估的主观性**：SRSC 依赖于 Qwen3.5-27B 的主观判断，尽管固定种子和结构化输出缓解了随机性，但模型偏好偏差依然存在。
- **基线能力不对称**：MultiWorld 的参数规模（5.60B）远超其他方法，且遵循官方 35 epoch 而非统一的 20k 更新预算，比较可能存在隐性偏差。
- **自报指标偏差风险**：解析器为论文自研，虽然经过冻结验证（GT 恢复率 ≥ 0.99），但特定于 Snake 数据集，跨任务的可迁移性未验证。

- **延迟数据未全面披露**：1,024 实体规模下服务器每 tick 推理的时间未在正文明确报告，实际游戏部署可行性（帧率要求）尚未证实。
