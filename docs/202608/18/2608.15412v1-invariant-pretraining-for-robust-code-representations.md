## 摘要
基于编码器的代码表示模型在克隆检测和代码分类等判别性任务中仍被广泛部署，其小尺寸和低推理成本是关键因素。然而，它们的鲁棒性很脆弱：在不变程序下，以不同句法形式编写的语义等价代码，即使程序行为不变，学习到的表示也会大幅退化。我们对这一鲁棒性差距进行了实证研究，涵盖四个编码器基线、两个下游任务和四个数据集，并提出了一种仅基于代码的最小持续预训练方法，可以显著缩小这一差距。我们的方法称为不变预训练（InvPT），对语料库应用语义保持变换，并将掩码语言建模与多正样本监督对比学习相结合，该对比学习将同一源函数的所有增强视为正样本，混合自对比对（相同代码，不同掩码）和不变对比对（变换后的代码），以产生难度不同的正样本。与之前的对比代码编码器不同，InvPT不需要成对的自然语言数据。在我们的评估中，InvPT在变换后的测试集上鲁棒性提升最高可达克隆检测11个百分点、代码分类19个百分点，同时标准准确率持平或提高，我们的消融实验表明多正样本不变对比是提升的主要来源。我们的目标不是提出新目标，而是仔细衡量编码器鲁棒性在何处失效，以及一个简单的仅基于代码的方法能在多大程度上恢复它。

## Abstract
Encoder-based code representation models remain widely deployed for discriminative tasks such as clone detection and code classification, where their small size and low inference cost are decisive. Their robustness, however, is fragile: under invariant programs, semantically equivalent code written in different syntactic forms, learned representations degrade substantially even though program behavior is unchanged. We present an empirical study of this robustness gap across four encoder baselines, two downstream tasks, and four datasets, together with a minimal code-only continued pretraining recipe that closes much of it. Our method, invariant pretraining (InvPT), applies semantic-preserving transformations to the corpus and combines masked language modeling with multi-positive supervised contrastive learning that treats all augmentations of the same source function as positives, mixing self-contrast pairs (same code, different masks) with invariant-contrast pairs (transformed code) for positives of varying difficulty. Unlike prior contrastive code encoders, InvPT does not require paired natural-language data. Across our evaluation, InvPT improves robustness on transformed test sets by up to 11 percentage points on clone detection and 19 on code classification while matching or improving standard accuracy, and our ablations isolate multi-positive invariant contrast as the main source of the gains. Our aim is not a new objective but a careful measurement of where encoder robustness breaks and how far a simple, code-only recipe can recover it.

- **核心问题**：基于编码器（encoder）的代码表示模型（如 CodeBERT、GraphCodeBERT）在克隆检测、代码分类等判别性任务中仍被广泛部署，但其对**语义等价的语法变体程序**（即"不变程序"，invariant programs）鲁棒性很差——即使程序行为完全不变，输入层面的微小句法变化会导致表示空间发生大幅漂移，从而显著降低下游任务性能。
- **研究动机**：
  - 现代语言句法灵活，开发者常用不同写法表达相同逻辑（如 `for` 循环与 `while` 循环互转、变量重命名等），这些自然变化在实践中极为常见。
  - 已有预训练模型因训练目标鼓励对表层 token 的敏感性，导致对这类天然变化的鲁棒性先天不足。
  - 以往研究（如 SPAT、ContraBERT）要么聚焦微调阶段，要么依赖双模态（NL-PL）配对语料，且未系统量化这一鲁棒性差距。
- **整体含义**：论文不在于提出全新目标函数，而是**系统性度量**编码器在不变程序下的鲁棒性失效程度，并探索一个足够简单的、纯代码（code-only）的持续预训练方案能在多大程度上恢复这一差距，为低成本部署场景下的模型鲁棒性改进提供了切实可行的路径。

## 2. 论文提出的方法论：核心思想、关键技术细节与流程

### 2.1 核心思想

InvPT（Invariant Pretraining）是一种**仅使用代码语料的持续预训练**方法。其核心假设是：语义保持的变换（semantics-preserving transformations）本身就蕴含了足够的监督信号，无需自然语言（docstring）配对，即可引导编码器学习对表面形式变化的不变表示。

### 2.2 技术组成

该方法由三个核心组件构成：

1. **不变代码变换（Invariant Code Transformations）**：
   - 在 AST 级别实现六种语义保持变换算子，分为两类：
     - **语法类**：变量重命名（VarRe）、`while` 转 `for`（W2F）、`for` 转 `while`（F2W）、`x++` 转 `x += 1`（PP2AA）、`x += 1` 转 `x = x + 1`（AA2EA）。
     - **分支类**：条件反转并调换分支（RevIf）。
   - 每个算子都有严格的前置条件以保证语义等价，例如 F2W 要求循环体不含 `continue`，PP2AA 要求自增结果未被消费，AA2EA 在 Python 中因无法静态检查类型而仅作为启发式等。
   - 实现上复用 Yu et al. 的 Java 算子、clang 处理 C/C++、Python 3 ast 模块处理 Python。

2. **不变对比学习（Invariant Contrastive Learning）**：
   - 使用**单共享编码器**（而非动量编码器），以原始代码与变换代码共同计算 MLM 损失：
     $$
     \mathcal{L}_{\text{MLM}}(X) = -\frac{1}{|M_X|}\sum_{x \in M_X} \log P(x|X')
     $$
   - 总目标为：
     $$
     \mathcal{L}(X, X_{\text{inv}}) = \frac{\mathcal{L}_{\text{MLM}}(X) + \mathcal{L}_{\text{MLM}}(X_{\text{inv}})}{2} + \alpha \mathcal{L}_{\text{SupCon}}
     $$
   - **多正样本监督对比掩码**：对每个源函数计算确定性哈希标识符，同源的所有增强（包括同批次中的不同算子变换）均视为正样本，从而避免 InfoNCE 将同义样本误判为负样本（false-negative）的问题。采用 SupCon 损失：
     $$
     \mathcal{L}_{\text{SupCon}} = -\frac{1}{|\mathcal{A}|} \sum_{i \in \mathcal{A}} \frac{1}{|\mathcal{P}(i)|} \sum_{p \in \mathcal{P}(i)} \log \frac{\exp(\text{sim}(\mathbf{z}_i, \mathbf{z}_p))}{\sum_{j \neq i} \exp(\text{sim}(\mathbf{z}_i, \mathbf{z}_j))}
     $$
   - 其中 $\text{sim}(\mathbf{u}, \mathbf{v}) = \mathbf{u}^T\mathbf{v}/\tau$，温度 $\tau=0.1$。

3. **混合难度对比对（Mixed-Difficulty Contrastive Pairs）**：
   - **Self-contrast（自对比）**：同一代码通过不同的 dropout 掩码（由 15% MLM 掩码概率决定）构成正对，是"易"样本。
   - **Invariant-contrast（不变对比）**：原始代码与语义等价变换后的代码构成正对，是"难"样本，如 F2W 和 VarRe 可使正对之间几乎无共享 token。
   - 两种难度正样本同时呈现，而非分阶段课程学习，以避免分布偏移和灾难性遗忘。

## 3. 实验设计

### 3.1 任务与数据集

- **下游任务**：
  - **克隆检测**：以 MAP@R 为指标，检索语义等价的程序。
  - **代码分类**：预测程序的功能类别（问题编号），以 accuracy 为指标。
- **数据集**：
  - **POJ104**：104 个问题，每题 500 个 C/C++ 解决方案。
  - **CodeNet 三个子集**：Java250、Python800、C++1400。
  - 刻意将 C/C++ **排除**在预训练语料之外，以检验跨语言迁移能力。
- **预训练语料**：CodeSearchNet 的 Java 和 Python 子集（六种算子均适用）。

### 3.2 对比模型

- 四个基础编码器基线：**CodeBERT**、**GraphCodeBERT**、**ContraBERT_C**、**ContraBERT_G**。
- 各自的 InvPT 版本：InvCodeBERT、InvGraphCodeBERT、InvContraBERT_C、InvContraBERT_G。
- 另纳入 **CodeSage**（1.3B）和 **ModernBERT** 作为更大规模参考点（不进行 InvPT 训练）。

### 3.3 评估方式

- **标准准确率**：原始（未变换）测试集上的表现。
- **鲁棒性**：对测试集**累积施加全部六种变换**（组合方式在训练中未见），衡量模型对未见过变换组合的不变性。

  - 鲁棒性测试仅限于预训练所用算子族内的组合，不覆盖其他类型的语义保持变换。

## 6. 论文的主要结论与发现

1. **鲁棒性差距确实存在且严重**：所有基线编码器在变换后的测试集上性能显著下降，例如 GraphCodeBERT 在 C++1400 克隆检测上从 58.76 降至 30.26。
2. **InvPT 全面改善了鲁棒性**：在全部 16 组模型–数据集比较中，InvPT 均提升了变换测试集上的表现；克隆检测中位提升 **+8.07 个百分点**（最高 +11.04），代码分类中位提升 **+3.56 个百分点**（最高 +19.16）。
3. **标准准确率不受损**：InvPT 在几乎所有基准上匹配或小幅提升原始测试集的表现。
4. **多正样本不变对比是主要增益来源**：消融实验表明去掉对比损失后性能下降最显著（最高 -4.52 pp），自对比提供稳定的补充增益（约 0.5–1.1 pp）。
5. **自然语言配对不必要**：加入 NL 描述的效果方向不一致且幅度很小（平均不到 1 个百分点），不足以证明双模态语料的必要性。
6. **跨语言迁移成立**：仅用 Java/Python 的不变预训练即可在 C/C++ 下游任务上获得鲁棒性收益，说明结构不变性可以跨语言泛化。
7. **恢复程度有限**：InvPT 仅恢复了原始到变换测试集性能差距的中位 29.6%（克隆检测）和 8.7%（分类），大部分差距仍然存在。

## 7. 优点

- **方法极简且实用**：纯代码、无需 NL-PL 配对、可在已有编码器上直接做低成本持续预训练，便于工业落地。
- **多正样本掩码设计巧妙**：解决同源增广在 InfoNCE 下被误推开的假阴性问题，且实现无需跨进程协调（基于源文件哈希）。
- **实验设计严谨**：
  - 跨语言持有（held-out）设置（C/C++ 完全不参与预训练）是验证泛化性的强设计。
  - 变换测试集使用未见的组合，避免与训练分布重合的乐观偏差。
  - 消融实验精确隔离了各组件贡献。
- **诚实刻画局限性**：明确声明只声称对算子族的不变性而非普遍鲁棒性，并讨论 Python AA2EA 的语义保持缺陷。
- **定性可视化佐证**：t-SNE 结果表明 InvPT 产生了明显更紧凑、分离更清晰的语义簇。

## 8. 不足与局限

- **实验覆盖不足**：
  - 所有配置仅单次运行，缺乏多随机种子统计显著性检验。
  - 仅覆盖竞赛编程类数据集（POJ104、CodeNet），不含工业代码库，代表性有限。
  - 未与"下游微调时做数据增强"这一更简单基线做对照。
  - 未与 Corder、ContraCode 的 InfoNCE 版本做受控对比，无法证明多正样本掩码的独立优势。
- **鲁棒性声明的范围有限**：变换测试集来自预训练所用同一算子族，对未见过的重写类型（自然重构、编译器优化等）的鲁棒性未知。
- **变换的正确性非形式化保证**：自动变换可能有边界情况改变行为（尤其 Python 的 AA2EA），影响比例未测量。
- **架构局限**：实验仅在 125M 参数编码器上验证；对 CodeSage（1.3B）和 ModernBERT 只作参考比较，未应用 InvPT，难以判断方法在大规模模型上的推广性。
- **语言覆盖有限**：算子设计基于 Java/C/C++/Python 的语法特性，扩展至 Haskell、Rust 等语义差异大的语言需大量工程工作。
- **任务局限**：仅评估判别性任务（克隆检测、分类），对生成任务需满足等变性（equivariance）而非不变性，论文未做实证验证。
